# ThatPerson 第三期反馈诊断与下期修复计划

> 关联：`ThatPerson第三期试用反馈-20260811.md`（用户反馈原文）
> 依据：`src/parser/archive.ts`、`src/cli.ts`、`src/chat.ts`、`src/skill.ts`、`关于ThatPerson-Agent项目第三版提示词.md`

## 一、已实证问题（诊断结论）

### P0 · 归档逻辑漏洞 —— ✅ 实证复现，与用户总结一致

对用户原话跑 `extractArchives` 结果：

```
IN: 你记得我喜欢干什么嘛
   [偏好] 用户喜欢「干什么嘛」，明确陈述。  置信度=高      ← 疑问句被当喜好对象

IN: 其实我不喜欢下雨天
   [偏好] 用户不喜欢「下雨天」，明确陈述。  置信度=高
   [偏好] 用户喜欢「下雨天」，明确陈述。  置信度=高  <conflict>   ← 同句双极性

IN: 我都不确定我喜不喜欢上课
   [偏好] 用户不喜欢「上课」，明确陈述。  置信度=高
   [偏好] 用户喜欢「上课」，明确陈述。  置信度=高  <conflict>   ← 用户说"不确定"仍标"高"
   [经历] 用户上课，感受：不喜欢。  置信度=高
```

**根因**（`src/parser/archive.ts` PREF_RULES 正向规则）：
1. 否定词不拦截：`不` 不在前置可选项，正则可从「不喜欢…」的「喜欢」处匹配 → 正负双极性。
2. 疑问词不过滤：`干什么嘛` 等疑问被 `喜欢` 后捕获 16 字吞掉，无 wh-词/停用词过滤。
3. 用户不确定性（「不确定…喜不喜欢」）未降置信度，仍标「高」。

**与提示词冲突**：违反 3c「负向偏好只取否定词前名词短语」；3e④ BC-2 未覆盖「同句双极性」类，现有 BC 全绿但漏检。

### P1 · 元认知仅"功能描述" —— ✅ 确认，根因结构性

- 运行时**无 function-calling / 工具层**：`chat.ts` 仅一次普通 `fetch` 文本生成。
- Agent 无法执行「检查工作目录」，只能答应+虚构动作，而非按 edge_cases 诚实拒绝。
- 提示词把元认知写成人格描述，无行为回路 → 落地缺口。

### P1 · Agent 无"肢觉" —— ✅ 确认，两层根因

- **CLI 路由死代码**：`cli.ts` 仅当 `line.startsWith('/')` 时调用 `matchSkill`，`trigger_keywords`/description 自动触发路径在 CLI 中永远走不到 → 自然语言永不触发 Skill。
- **LLM 可见性缺口**：skill 清单不注入 system prompt；`/` 命中后仅打印 SKILL.md 前 3000 字符到控制台，不喂给 LLM、不执行脚本。
- **与提示词冲突**：第 5 项要求 Skill「发现→激活→执行」，代码仅「发现」（列表）——「激活」「执行」未实现。
- 补充：示例四 Agent 诚实拒绝，是**遵守** edge_cases「不知道/做不到要明说」；问题在能力清单与执行机制未交付给运行时。

### P2 · CLI 执行层脱钩 —— ✅ 确认（一处表述失实）

- 失实：总结写「CLI 退出」；原文 CLI 未退出，是用户随后 `exit`。
- 成立：CLI 纯消息通道，无指令分发、无工具结果回传。

## 三、下期（第 4 期）修复计划

### P0 · 归档极性判断（最高优先）

- [ ] 用户表达不确定（「不确定/也许/可能/不一定」+ 喜欢）→ 降为「中」置信度或标记待确认，不标「高」。
