## A. 重写工具调用层（Tool First）—— P1 主解

> 依据：Tool Use 模式"让 Agent 写代码调用工具"的标准化/安全/可扩展三原则 + 重写工具调用层.md 四步 + ReAct 循环的"思考→行动→观察→再思考"。

### A1. 工具定义层：src/tools/registry.ts（新）

统一工具注册表，每个工具 = JSON Schema 定义（对齐总结缺失组件表第一项"工具定义"）：

```ts
// src/tools/types.ts
export interface ToolDef {
  name: string;                 // 唯一、snake_case
  description: string;          // 一句话 + 能力边界（禁止做什么）
  parameters: Record<string, unknown>; // JSON Schema（type/properties/required）
  handler: (args: Record<string, unknown>) => ToolResult; // 宿主执行
  policy: 'read' | 'write' | 'danger';  // 权限分级（安全默认值）
}

export interface ToolResult {
  ok: boolean;
  data?: unknown;               // 成功：结构化结果（截断到预算）
  error?: string;               // 失败：机器可读原因，供模型修正参数重试
}
```

**第 5 期首批工具清单（白名单注册，未注册一律拒绝）：**

| 工具 | 权限 | 说明 |
| :-- | :-- | :-- |
| list_directory | read | 列目录（现 check directory 的能力并入，白名单目录内） |
| read_file | read | 读文件（白名单目录：记忆目录、用户显式允许的目录） |
| read_vault_note | read | 读 Obsidian 笔记（vault-api-bridge 的读能力，node 原生实现，不依赖 Python） |
| search_vault | read | 关键词/标签搜索笔记（对标 vault_api.py 的 search/list_notes 的常用子集） |
| search_memory | read | 检索历史记忆（复用 chat.ts 的 retrieveRelevant 逻辑，作为工具暴露） |
| append_memory | write | 主动写入记忆（替代"只靠轮末自动归档"，支持"现在记住 XXX"） |
| edit_present | write | 自动填入 present/（支撑下期方向 1：改名/改称呼 → 写入 identity.md） |
| run_shell | danger | 默认**禁用**；THATPERSON_ENABLE_SHELL=true 且二次确认才注册（vault 脚本桥接的通道） |

### A2. API 改造：支持 Function Calling（chat.ts）

- chat() 增加可选 tools?: ToolDef[]；请求体补 tools（DeepSeek 原生 function calling 格式）+ tool_choice: 'auto'。
- 工具描述**精简**（一句话 + 参数名），不塞长文档，控制 token（Tool Use 原则 3）；工具描述由宿主静态提供，**不来自对话/记忆内容**（注入防护）。
- 保留现有纯文本路径（tools 为空时行为不变），保证 111 个既有测试不回归。

### A3. 工具执行器：src/tools/executor.ts（新）

- 注册表 name → handler 的 Map；未注册 → {ok:false, error:'unknown-tool'}。
- **参数校验**：执行前按 JSON Schema 校验类型/必填/枚举；路径类参数做 path.resolve + 前缀白名单（~/.thatperson、项目目录、vault 仓库目录），拒绝 .. 与白名单外绝对路径（延续 SEC-8 口径）。
- 权限门：read 默认放行；write 限记忆/present 目录；danger 需 config 开关 + 用户确认（复用 inquirer 确认）。
- 结果截断（如 4000 字符）后进入下一轮上下文，防工具输出撑爆预算。

### A4. 回灌闭环：ReAct 循环（cli.ts / 新 src/agent/loop.ts）

对齐"工具结果回灌"与 ReAct 循环控制：

```
第 1 次请求（system + 历史 + 用户，带 tools）
  └─ 返回 tool_calls? ──否──> 直接输出最终回复
  └─ 是：逐条执行 → 追加 {role:'assistant', tool_calls} + {role:'tool', tool_call_id, content}
  └─ 第 2 次请求（消息带工具结果）
      └─ 再 tool_calls? ──否──> 输出最终回复
      └─ 是：继续……（上限 MAX_TOOL_ITERATIONS = 5，防无限循环）
```

- **失败恢复**（ReAct 坑 3）：工具失败以 {ok:false,error} 作为观察结果回灌，模型可修正参数重试；连续失败 3 次允许"认输"诚实告知（present 既有"禁止答应+虚构动作"红线在此自然成立）。
- **完成判定**（ReAct 坑 2）：无 tool_calls 即终止；max_iterations=5 硬上限。
- 工具调用记录写 logs/tool-YYYY-MM-DD.jsonl（时间/工具/参数摘要/状态，不落 Key、不落敏感原文）——可观测性（ReAct 显式化收益落地）。

### A5. 技能 → 工具桥接（Skill Loader）

- SKILL.md frontmatter 增加可选 tools: 声明（如 vault-api-bridge 声明 read_vault_note/search_vault）。
- 触发技能时把其声明的工具**动态注册**进本轮 tools 列表（可扩展原则；技能=工具组合说明书，执行归工具层）。
- 保留 <技能清单> 摘要注入（能力自省），<技能清单> 与 <工具清单> 双边界，SKILL.md 原文仍不进 System（SEC-5 不后退）。
- vault-api-bridge 落地路径：先 node 原生实现常用子集（read/search/list），Python 脚本桥接走 run_shell（默认关），两步走。

### A6. 验收

- 示例一场景全通：从知识库中读取2026年7月31日的日记 → 模型调用 read_vault_note → 真实返回内容并回应日记内容。
- 新增测试：工具 schema 校验、路径穿越拒绝、未注册工具拒绝、循环上限、tool_result 边界注入、danger 工具禁用态（同步"下期方向 6"）。

## B. 记忆归档质量工程 —— P2/P3 主解

### B1. 规则版三闸修复（立即可做，src/parser/archive.ts）

1. **单句单条目闸**：extractPrefs 对同一句子（sentenceBounds 范围）同一极性只保留第一次命中（按句子+极性去重），杜绝"最喜欢……喜欢……"双条目。
2. **无意义对象闸**：cleanObject 增加占位词黑名单（事情/东西/感觉/时候/样子/氛围/状态…），命中则视为无对象；正向无对象跳过（已有逻辑），负向回溯对象同样过滤。
3. **不确定不产经历闸**：extractExperiences 在句子含 UNCERTAIN_WORDS（不确定/也许/可能/说不定…）或否定结构时**跳过**，防止"不确定喜不喜欢看书 → 经历：看书，感受：不喜欢"的过度推断。

### B2. LLM 语义归档增强（中长期）

- 维持 THATPERSON_LLM_ARCHIVE 开关（默认关闭、离线安全不后退），但升级约束：
  - system prompt 增加硬规则：insight 必须是对 dialog 的语义概括，禁止直接截取原话片段；同一条 dialog 不得产出多条同类型条目；用户表达不确定时 confidence 用中，且不得同时产出偏好与经历。
- 每日摘要（buildSessionSummary 的 topics/mood）也可走 LLM 增强，提升日记类内容的主题提炼质量。

### B3. 长文本"内容感知"（P2 核心）

- cli.ts 检测 userText 长度（如 >200 字）进入"内容模式"：
  1. 归档输入 = 全文（规则提取对长文整体分析，而非只看首句）；
  2. 回复指令注入：「用户分享了具体内容（日记/文章）时，先回应内容本身，再回应动作」；
  3. 检索：长文本拆分段落入检索语料，确保日记里的关键词可被后续检索命中。

### B4. 验收

- P2/P3 三个实测反例（用户喜欢「事情」、日记 0 归档、不确定双重归档）转为回归用例，修复后全绿。
- badcases.test.ts 新增 BC-10（同句多锚点单条目）、BC-11（不确定不产经历）、BC-12（长文本内容归档）。

## 附：与两份设计模式的对应关系

| 设计模式要点 | 本方案的落点 |
| :-- | :-- |
| ReAct：思考显式化、可观测可调试 | A4 循环 + 工具审计日志（logs/tool-*.jsonl） |
| ReAct：行动原子化、失败恢复、循环上限 | A3 单工具单职责 + A4 {ok:false,error} 回灌 + MAX_TOOL_ITERATIONS=5 |
| ReAct：思考有结构、聚焦当下 | A2 工具描述精简 + prompt 引导"先决定下一步调用，再调用" |
| Tool Use：工具定义在代码库不在上下文 | A1 registry + A2 精简描述（防 token 爆炸） |
| Tool Use：接口标准化、参数类型注解 | A1 JSON Schema + A3 执行前校验 |
| Tool Use：代码沙箱/安全检查 | A3 参数校验 + 路径白名单 + 权限分级 + danger 默认禁用 |
| Tool Use：可扩展（动态注册） | A5 SKILL.md frontmatter tools: 声明 + 动态注册 |
