# ThatPerson 安全测试工具操作指南

> 日期：2026-08-12
> 适用范围：ThatPerson 第 4 期 Dev/QA（D-1~D-4 / Q-1）及后续 Agent 项目
> 配套落地：`tests/security.test.ts`（SEC-1~9）、`tests/fuzz.test.ts`（FZ-1~5，第 4 期新增）、`tests/badcases.test.ts`（BC-1~9）、`tests/isolation.test.ts`（IS-1~3）
> 核心原则：沿用《安全测试环境搭建指南-20260810.md》——**离线、免 Key、隔离、可重复、快速**

## 一、套件总览（第 4 期现状）

| 套件 | 编号 | 守护承诺 |
| :--- | :--- | :--- |
| 安全回归 | SEC-1~9 | 注入边界 / 写盘转义 / 路径穿越 / Skill / 静态卫生 / 离线 |
| 载荷模糊 | FZ-1~5 | 注入载荷变体下四个输入面边界不失效（KeySpecs S-17） |
| Bad Case | BC-1~9 | 归档极性 / 疑问句过滤 / 不确定性降级 / 假模式 / token 预算 / 压缩 |
| 测试隔离 | IS-1~3 | 临时 home / 真实目录零变化 / 环境变量恢复 |
| CLI 生态（他人负责） | cli.test.ts | 内部指令表 / --version / --help / 全局指令 |
| 更新检查（他人负责） | update-check.test.ts | 12h 缓存 / 404 静默 / version 对比 |

运行入口统一为 `npm.cmd test`（Windows 下勿用 `npm.ps1`），全部离线、零 API。

## 二、怎么跑

```powershell
npm.cmd test                                  # 全量：tsc 双段编译 + node --test
npm.cmd test -- --test-name-pattern SEC-      # 只跑安全回归（SEC-1~9）
npm.cmd test -- --test-name-pattern FZ-       # 只跑载荷模糊（FZ-1~5）
npm.cmd test -- --test-name-pattern BC-       # 只跑 Bad Case（BC-1~9）
npm.cmd test -- --test-name-pattern IS-       # 只跑隔离守卫（IS-1~3）
```

单文件（已编译产物）：

```powershell
npx.cmd tsc -p tsconfig.test.json             # 测试编译到 dist-test/
node --test dist-test/tests/fuzz.test.js      # 只跑模糊套件
```

注意：并行开发期间 `tsc --noEmit` 可能因他人 src/ 半成品失败。先 `git diff src/` 判断是否与你无关，**不得为通过编译而改弱已确定的契约断言**（除非口径确已过时）。

## 三、模糊测试怎么扩展

变体源集中在 `tests/fuzz.test.ts` 的 `injectVariants()`，每加一行变体即自动纳入全部验证面：

- 大小写混合：`IgNoRe`、`SYSTEM PROMPT`
- Unicode 全角 / 转义：`ｓｙｓｔｅｍ ｐｒｏｍｐｔ`、`ＡＬＬ`
- 多层闭合标签：`</memory><memory>`、`</memory><script>alert(1)</script>`
- CRLF 注入：`\r\n</memory>`
- 混合编码引号：`“忽略以上指令”`、`『…』`

验证面（KeySpecs S-17）：

| 面 | 用例 | 断言方式 |
| :--- | :--- | :--- |
| ① 写盘转义 | FZ-1 | 载荷 `< >` → `&lt; &gt;`，CRLF 被扁平化；原始标签零残留（SEC-2 口径） |
| ② 边界不失效 | FZ-2/3/4/5 | `<memory>`、`<检索命中>`、`<早前对话摘要>`、Skill 内容边界（SEC-1/3/9/5 口径） |
| ③ LLM 归档 schema | 待 S-13 落地 | LLM 伪造条目被 schema 校验拒绝（当前规则版无此面） |

写断言时的三个已知坑（已内置处理）：

1. 指令区文字本身会提及 `<memory>` / `<检索命中>`，定位真实数据块要用 `lastIndexOf`，不要数开标签个数。
2. `retrieveRelevant` 命中行截断到 120 字符，长载荷用「前缀包含」断言（FZ-3 已用 `escaped.slice(0, 30)`）。
3. 归档文件本身含 `<dialog>` / `<conflict>` 等结构标签，只校验载荷内的 `< >`，不能断言全文件无尖括号。

**已知缺口（QA 发现 #1）**：`FZ-4b` 目前红灯——带闭合/脚本标签的载荷经 `summary` 参数直接进入 `<早前对话摘要>` 块时，可提前闭合摘要块。根因：`src/cli.ts` 折叠摘要 `用户说「${u.content}」` 未对用户文本做转义/净化，且 S-13 的 LLM 归档 schema 校验尚未落地。修复方向：summary 输入侧转义 `< >`，或实现 LLM 归档 schema 校验后拒绝伪造条目。

## 四、--mock 离线验证

```powershell
npm.cmd run chat:mock        # 离线持续对话（tsc 构建 + --mock）
npm.cmd run mock             # 单次离线指令
$env:THATPERSON_HOME = $env:TEMP\thatperson-sec-home   # 隔离 home，不碰真实 ~/.thatperson
```

- `--mock` 不读 Key、不发网络（SEC-7 守卫）；测试进程禁止调用 `loadEnv()`。
- 验证归档污染：临时 home 与项目 `history/` 不应出现攻击载荷；真实 `~/.thatperson/` 保持原样。
- 归档极性实证：`--mock` 对话输入「其实我不喜欢下雨天」，应只归档负向、无双极性（BC-7 判据）。

## 五、真实模型红队（可选、需人工）

标准方式：复用归档脚本 `安全专项\scripts\redteam-run.js`（第 4 期红队执行逻辑，内置 13 组用例表，默认关闭）。

```powershell
npm.cmd run build                                  # 先构建 dist/（脚本加载 dist/src/chat.js 走真实 System 组装）
$env:THATPERSON_REDTEAM = '1'                      # 显式开关门禁（不设则拒绝运行，exit=2）
$env:AAGENTDS_REDTEAM_API_KEY = '<测试Key>'        # 红队专用（优先）；缺省回落备用/主 Key（带警告）
node 安全专项\scripts\redteam-run.js --out redteam-results.json        # 全量 13 组
node 安全专项\scripts\redteam-run.js --cases A1,C3,D1 --out out.json   # 只跑指定子集
```

脚本特性（对齐安全红线）：

- **默认拒绝运行**：未设置 `THATPERSON_REDTEAM=1` 直接退出（exit=2），不产生任何请求。
- **Key 优先级**：`AAGENTDS_REDTEAM_API_KEY`（红队专用）> `AAGENTDS_ARCHIVE_API_KEY`（备用）> `AAGENTDS_API_KEY`（主 Key）；回落主 Key 时打印醒目警告（需 BUCISHUI 显式授权）。
- **全程隔离**：`THATPERSON_HOME / THATPERSON_MEMORY_DIR` 指向 `%TEMP%\tp-redteam-*`，跑完自动删除；真实 `~/.thatperson/` 与项目 `history/` 零写入。
- **不打印 Key / 响应脱敏**：错误体 `sk-***` 脱敏；仅向白名单端点 `https://api.deepseek.com` 发起请求。
- **结果 JSON**：逐用例载荷 + 模型回复 + 耗时，供人工逐条判定 PASS/FAIL 并归档；用例表在脚本 `CASES` 数组可扩展。

兜底手工方式（脚本不满足定制场景时再使用）：

```powershell
$env:THATPERSON_HOME = $env:TEMP\thatperson-live-home   # 独立 home
$env:AAGENTDS_API_KEY = <测试用低额度Key>                # 独立测试 Key
npm.cmd run chat
```

边界要求：

- **测试 Key 不得复用主 Key**：`.env` / `API-key.md` 中的是主 Key，只用于日常开发；红队另配独立低额度测试 Key，用完即弃。
- 只验证**真实模型行为**（注入是否被模型拒绝、边界是否守得住），记忆与配置仍全部落在临时目录。
- 跑完删除临时目录，并核对真实 `~/.thatperson/` 与项目 `history/` 零变化（IS-2 口径）。
- 离线只能验证边界，不能验证模型行为；红队是离线套件的补充，不是替代。

## 六、供应链评审检查点

第 4 期已评审结论（KeySpecs S-16 / CR-017）：`boxen / chalk / figlet / inquirer / log-symbols / ora / commander` 全部 MIT、来源 `registry.npmjs.org`、仅终端表现与参数解析，无网络外发、无文件越权；使用面仅限 UI 层与全局命令解析，核心逻辑保持零依赖。

后续任何新增运行时依赖，先过以下检查点再引入：

| 检查点 | 要求 |
| :--- | :--- |
| 来源 | 仅 `registry.npmjs.org`（或已评审镜像），核对 lock 文件锁定版本 |
| 许可 | MIT / BSD / Apache-2.0 等宽松许可，记录在案 |
| 权限面 | 无网络外发、无文件越权、无 eval/动态执行 |
| 使用面 | 仅限 UI 层与命令解析，不进入核心记忆/解析逻辑 |
| 白名单登记 | 同步登记进 SEC-6 ③ 的「非白名单网络端点」扫描白名单 |

SEC-6 口径（第 4 期更新，已落地 `tests/security.test.ts`）：不再断言「零运行时依赖」；改为——src 无硬编码 Key、网络仅白名单端点 `https://api.deepseek.com`、无对非白名单域名的 fetch/网络调用、Key 明文仅允许存在于 `.env` / `API-key.md`（均被 `.gitignore` 排除）。

## 七、常见坑速查

1. **PowerShell 拦截 npm**：用 `npm.cmd`，勿用 `npm.ps1`。
2. **测试读到 .env**：测试进程禁止 `loadEnv()`；必要时先 `Remove-Item Env:AAGENTDS_API_KEY`。
3. **污染真实记忆**：任何写盘用例必须用 `os.tmpdir()` 临时目录（IS-1 守卫）。
4. **网络端点漂移**：新增外部调用必须同步 SEC-6 白名单断言，防止供应链端点混入。
5. **并行开发编译红**：他人 src 半成品可能让 `tsc --noEmit` 失败，先 `git diff` 定位归属，勿改弱断言。
