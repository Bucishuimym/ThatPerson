## 第一步：定义工具（Tools Definition）

在 src/tools/ 下创建一个 tools.ts，用 JSON Schema 描述 ThatPerson 可用的工具：

```typescript
// src/tools/tools.ts
export const tools = [
  {
    type: "function",
    function: {
      name: "read_file",
      description: "读取指定路径的文件内容",
      parameters: {
        type: "object",
        properties: {
          path: { type: "string", description: "文件的绝对或相对路径" }
        },
        required: ["path"]
      }
    }
  },
  {
    type: "function",
    function: {
      name: "write_file",
      description: "将内容写入指定路径的文件",
      parameters: {
        type: "object",
        properties: {
          path: { type: "string", description: "目标文件路径" },
          content: { type: "string", description: "要写入的内容" }
        },
        required: ["path", "content"]
      }
    }
  },
  // 你可以按这个格式继续添加：list_directory, execute_skill, search_memory...
];
```

为什么要用 JSON Schema？
因为大模型（DeepSeek）原生支持 Function Calling。你只需要把这段描述作为 tools 参数传入 API 调用，模型就会在需要时返回结构化的工具调用指令，而不是靠提示词“猜”。

## 第二步：改造 API 调用（支持 Function Calling）

修改你的 agent.ts 或 cli.ts 中调用 DeepSeek 的代码：

```typescript
import { tools } from './tools/tools';

const response = await client.chat.completions.create({
  model: "deepseek-v4-flash",
  messages: messages,
  tools: tools,           // 👈 把工具定义传给模型
  tool_choice: "auto",    // 👈 让模型决定是否调用工具
  stream: false
});
```

现在，当模型认为需要读取文件时，它会在 response.choices[0].message.tool_calls 中返回一个结构化指令，而不是在 content 里回复一段文字。

## 第三步：实现工具执行器

在 src/tools/executor.ts 中，根据 tool_calls 执行真正的操作：

```typescript
// src/tools/executor.ts
import { readFileSync, writeFileSync } from 'fs';

export function executeToolCall(toolCall: any): string {
  const { name, arguments: args } = toolCall.function;
  const parsedArgs = JSON.parse(args);

  switch (name) {
    case 'read_file':
      return readFileSync(parsedArgs.path, 'utf-8');
    case 'write_file':
      writeFileSync(parsedArgs.path, parsedArgs.content, 'utf-8');
      return '写入成功';
    // ... 其他工具
    default:
      return `未知工具: ${name}`;
  }
}
```

## 第四步：将工具执行结果“回灌”给模型

当模型返回 tool_calls 时，你不能直接输出结果，而是要把执行结果作为一条新消息，再次发送给模型，让它基于结果生成最终回复。

```typescript
// 伪代码流程
const response = await callLLM(messages, tools);

if (response.tool_calls) {
  const toolResults = response.tool_calls.map(tc => {
    const result = executeToolCall(tc);
    return { tool_call_id: tc.id, output: result };
  });

  // 追加工具结果到消息列表
  messages.push({ role: "assistant", tool_calls: response.tool_calls });
  messages.push({ role: "tool", tool_call_id: toolResults[0].tool_call_id, content: toolResults[0].output });

  // 再次调用模型，让它基于工具结果生成最终回复
  const finalResponse = await callLLM(messages, tools);
  console.log(finalResponse.content);
}
```
