## 二、关键架构决策

### D1 · 记忆回灌从「全量注入」改为「四层按需注入」
- 画像层（identity/traits ≤1KB 全量）＋ 日期层（仅未来 14 天）＋ 动态层（检索命中 Top-K≤8）＋ 近期层（session_logs 三行）。
- 依据：上下文失控分析根因 1（全量注入 → 咖啡劫持）。检索命中层是唯一动态来源，回复指令限定「最多融入 1 条相关记忆」。

### D2 · 归档解析器「动宾短语」与「场景词过滤」
- 经历提取改为定位感受词后向前取最近的动宾短语，杜绝「去啊」吞掉「打篮球」。
- 负向偏好回溯时按场景词切分，对象定位到名词短语（燕麦拿铁 ≠ 咖啡馆）。

### D3 · 模式判定改为「跨轮」语义
- 单条消息永不产出「模式」；新增 `detectCrossTurnPatterns(userTexts)`，由 cli 维护最近 6 轮窗口，同主题跨 ≥2 轮才记录。
- 理由：单条消息三次提「咖啡」是强调而非稳定兴趣（BC-4）。

### D4 · 记忆压缩与硬上限（3d）
- 每文件软上限 100 条；写入前检查，超限触发 compact（去重 → 低置信度 30 天衰减 → 同标签 >5 条折叠 → 硬上限截断）。
- summary 上限 2000 字，`foldSummary` 二次折叠保留最新部分。

### D5 · 全局目录外置到 ~/.thatperson（对标 ~/.claude）
- config.json / present / skills / logs 入用户目录；history 始终在项目目录。
- `THATPERSON_HOME` 环境变量可自定义；`ensureConfigDir` 已存在不覆盖。

### D6 · 记忆目录三档定位（发布场景修复）
- 规则：`THATPERSON_MEMORY_DIR` 显式指定 > 项目模式（cwd 即本项目，`<cwd>/history/`）> 全局模式（`~/.thatperson/history/`）。
- 动机：npm 全局包发布后，`process.cwd()` 是任意运行目录，记忆会散落且只读目录会写失败；改为「记忆跟随 Agent 数据目录」后，任意目录运行共享同一份记忆。
- 行为：本地开发不变（仍项目 `history/`）；发布部署记忆入用户目录，卸载/升级不丢记忆。

### D7 · Skill 调用「发现 → 激活 → 执行」
- 默认 `~/.thatperson/skills/`，项目 `.claude/skills/` 可选扩展，同名用户级优先。
- 触发：`/名称` 斜杠命令优先；`trigger_keywords` 自动触发。渐进式加载省 token。

## 三、关键教训

1. **示例即偏置**：预设示例用单一主题（咖啡）会让模型天然倾向该话题——示例必须多主题中性轮换并声明「仅演示格式」。
2. **记忆保存是代码职责，不是 LLM 职责**：归档由 `extractArchives` + `appendArchive` 自动完成，预设可以放心做减法。
3. **检索必须「只注入命中」，而非「全量之上追加检索」**：前者是预算控制，后者只是装饰。
4. **测试数据必须独立目录**：演示/测试数据用 `createMemoryStore(demoRoot)`，跑完即弃，禁止沉淀进 `history/`。
5. **API Key 零消耗原则**：本期所有验证走 `--mock` 离线模式，未发起任何真实 API 请求。
