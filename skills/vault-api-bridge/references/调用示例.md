# vault-api-bridge 调用示例

> 用于 skill `vault-api-bridge`。完整接口与参数以 `scripts/自动化脚本/适配Obsidian的自动化.md` 为准。
> 底层代码：`scripts/自动化脚本/vault_api.py`、`vault_reader.py`、`vault_query.py`、`vault_env.py`、`example_usage.py`。
> 本插件自动探测 Obsidian 与仓库，**不写死机器路径**，换电脑/换仓库无需改代码。

## 环境准备

```bash
python --version        # 需 >= 3.8
# 环境自检：确认 Obsidian 已装、有仓库，并自动挑选默认仓库
python vault_env.py     # 在 scripts/自动化脚本/ 目录下执行
# OCR 可选：pip install paddlepaddle paddleocr
```

## 最小可用脚本（自适应定位）

```python
import sys, pathlib

# 定位脚本目录：仓库内 9-插件 或 .claude/skills 下的 vault-api-bridge
SCRIPT_DIR = None
cwd = pathlib.Path.cwd().resolve()
for base in (cwd / '9-插件' / 'vault-api-bridge',
             cwd / '.claude' / 'skills' / 'vault-api-bridge',
             pathlib.Path(__file__).resolve().parent):
    cand = base / 'scripts' / '自动化脚本'
    if (cand / 'vault_api.py').exists():
        SCRIPT_DIR = cand
        break
if SCRIPT_DIR is None:
    raise RuntimeError('找不到 vault-api-bridge 脚本目录')
sys.path.insert(0, str(SCRIPT_DIR))

from vault_env import setup_api
api = setup_api()          # 自动探测默认仓库；也可 setup_api(r"<仓库绝对路径>")
api.initialize()

# 读单个笔记
note = api.execute("read_note", {"path": "0-收件箱/Agent开发团队职业规划.md"})
print(note["data"]["content"][:500])

# 搜关键词
hits = api.execute("search", {"keyword": "提示词"})
print(hits["count"])
for it in hits["data"]:
    print(it["path"], "|", it["title"])

# 列代码文件
code = api.execute("list_notes", {"ext": ".py"})
print(code["count"])
```

> 所有 `path` 均为仓库内相对路径；若仓库不是 PARA 结构，先 `get_info` 看 `categories`，用实际顶层目录名。

## 常用动作

| 动作 | 必备参数 | 说明 |
|------|---------|------|
| initialize | -（`force_rescan` 可选） | 首次必须，扫描仓库 |
| get_info | - | 仓库概览/统计/结构（含 `structure`、`categories`） |
| read_note / read_file | `path` | 读单文件（read_file 自动 OCR） |
| list_notes | `folder`/`ext`/`file_type`/`tag`/`category` | 列出文件 |
| search | `keyword`/`tags`/`folder`/`mode` | 搜索，mode 可取 keyword/tag/ocr/advanced |
| get_recent | `limit` | 最近修改 |
| get_diary_by_date | `date` | 按日期取日记 |
| get_tags / get_extensions | - | 标签云/扩展名统计 |
| get_ocr_status | - | 确认 OCR 是否可用 |

## 返回格式（判断成败）

```json
{
  "status": "success | error | partial_success",
  "action": "search",
  "data": { ... },
  "count": 5,
  "error": "...",   // status=error 时
  "message": "..."
}
```

先看 `status`：`success` 取 `data`；`partial_success` 查看 `errors`；`error` 先报告 `message` 再重试。

> 注意：`initialize` 的返回值是特殊结构——`stats` **直接挂在顶层**（`{status, message, stats}`），没有 `data` 包裹。取用统计时用 `r["stats"]`，别用 `r["data"]`。其余动作（read_note / search / list_notes / get_info 等）统一是 `data` 包裹，需经 `r["data"]` 取值。
