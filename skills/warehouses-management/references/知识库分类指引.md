# 知识库分类指引

## 一、文件夹定义

> **通用规则**：凡是自己撰写的原创内容（项目总结、学习笔记、日记、卡片、文章等），均需在笔记末尾由 AI 撰写一段**评价文字**，总结内容质量、理解深度或完成度，并附上 `#评价/` 标签作为简要标记（见第三章）。

### `0-收件箱` — 临时收件箱
- **用途**：所有新笔记、临时想法、待处理的文章链接、快速捕获的内容，**默认存放处**。
- **特点**：无需分类、无需整理，先记下来再说。
- **处理规则**：定期（如每日/每周）清理，将笔记移入对应文件夹或归档。AI 需定期扫描此文件夹，提示用户归类。
- **示例**：一闪而过的灵感、别人发来的链接、随手记的待办事项。
- **禁止**：存放已整理完成的笔记。

### `1-项目` — 项目
- **用途**：有明确**截止日期**和**产出目标**的短期任务。
- **特点**：每个项目通常有独立的文件夹，包含调研、进度、总结等子笔记。
- **生命周期**：项目完成后整体移入 `4-存档`。
- **示例**："写年终总结"、"开发某个功能"、"准备考试"、"装修房子"。
- **命名建议**：`项目名` 或 `项目名-开始日期`。

### `2-领域` — 领域知识
- **用途**：需要**长期关注和持续精进**的职责、学科或兴趣领域。
- **特点**：没有截止日期，是持续积累的过程。内容会不断增补和迭代。
- **示例**：`C++`、`Linux`、`个人成长`、`投资理财`、`心理学`、`健身`。
- **与项目的区别**：领域是"持续学习"，项目是"一次做完"。

### `3-资源库` — 资源库
- **用途**：按主题整理的**参考资料、学习笔记、读书笔记、论文摘要**等。
- **特点**：内容相对完整、结构化，是"已经消化过的知识"。
- **与领域的区别**：领域是"我正在学的"，资源库是"我学完整理好的"。
- **内部结构**：资源库内部按**内容类型**分子文件夹；主题维度由 `#主题/` 标签表达，两者不冲突。

| 子文件夹 | 用途 | 示例 |
|---------|------|------|
| `01-读书笔记` | 书籍、文章的读后感、书评、摘录 | 《寂寞的游戏》读后感 |
| `02-工具教程` | 软件的安装、配置、使用教程 | Claude CLI 安装教程、OpenClaw 使用指南 |
| `03-案例分析` | 对企业/项目/人物的商业模式、案例拆解 | 影视飓风商业模式画布 |
| `04-知识参考` | 语法、术语、概念等结构化参考速查 | Markdown 语法速查 |
| `05-环境清单` | 本机软件清单、目录树、环境配置记录 | 软件安装目录清单 |

> **默认类型标签**：`01-读书笔记`→`#类型/读书笔记`，`02-工具教程`/`04-知识参考`→`#类型/笔记`，`03-案例分析`→`#类型/文章`，`05-环境清单`→`#类型/清单`。

### `4-存档` — 存档
- **用途**：存放**已完成、不再活跃**的项目或过时信息。
- **特点**：只归档不删除，保留完整记录以备将来查阅。
- **内容**：已完结的项目文件夹、不再维护的笔记、过期的参考材料。
- **规则**：移入存档后原则上不再修改，只做只读查阅。

### `5-卡片盒` — 卡片盒
- **用途**：**原子化知识卡片**，一张卡片只讲一个概念。
- **特点**：
  - 每个卡片聚焦一个概念、术语或想法。
  - 卡片之间通过 `[[双向链接]]` 相互关联。
  - 追求简洁、清晰、独立。
- **示例**："什么是 RAII"、"虚函数表原理"、"CAP 定理"。
- **卡片结构建议**：
  ```markdown
  # 概念名
  - **定义**：一句话概括
  - **详解**：展开说明
  - **关联**：[[相关卡片1]]、[[相关卡片2]]
  - **来源**：出处或参考
  ```

#### 卡片盒内部组织规则

卡片盒按**来源**设立子文件夹，方便批量管理同一来源的卡片。

```
5-卡片盒/
├── 来源/
│   ├── 《代码大全》/
│   │   ├── RAII机制.md
│   │   ├── 虚函数表原理.md
│   │   └── ...
│   ├── 《思考，快与慢》/
│   │   ├── 系统1与系统2.md
│   │   └── ...
│   └── 个人灵感/
│       └── ...
```

- **子文件夹命名**：`来源/` 格式，书籍用书名号 `《》`，文章用标题，个人原创用 `个人灵感`。
- **同一来源的卡片必须**：
  1. 放在同一个子文件夹下；
  2. 在卡片的"关联"字段中使用 Wikilink `[[卡片名]]` 相互关联，形成知识网络。
- **跨来源关联**：不同来源的卡片如有概念重合，也可通过 Wikilink 关联，但不强制。
- **卡片模板**：
  ```markdown
  # 概念名
  - **定义**：一句话概括
  - **详解**：展开说明
  - **关联**：[[同来源卡片1]]、[[同来源卡片2]]、[[跨来源相关卡片]]
  - **来源**：《XXX书籍名》第N章 / 《XXX文章名》
  ```

### `6-日记` — 日记
- **用途**：**每日记录、灵感碎片、工作日志、复盘反思**。
- **特点**：按日期组织，以天为单位。内容可以是流水账、碎碎念、深度思考。
- **命名建议**：`YYYY-MM-DD.md` 或 `YYYY-MM-DD-星期几.md`。
- **可选内容**：今日完成、遇到的问题、灵感瞬间、感恩日记、明日计划。
- **模板参考**：见 `7-模板/日记模板.md`。
- **特殊标签**：个人日记需额外打上 `#jack六年之约` 标签，用于标记"六年之约"计划中的个人成长记录。
- **AI 评价**：每篇日记末尾由 AI 撰写一段评价文字，回顾当天的学习/成长收获，附上 `#评价/` 标签。

### `7-模板` — 模板
- **用途**：存放各类笔记的**模板文件**，配合 Obsidian 模板插件使用。
- **特点**：模板文件本身不记录内容，只提供结构框架。
- **常见模板**：
  - `日记模板.md` — 每日记录的标准结构
  - `项目模板.md` — 新建项目时的目录结构
  - `卡片模板.md` — 原子卡片的格式
  - `读书笔记模板.md` — 读书笔记的框架
  - `会议记录模板.md` — 会议纪要的标准格式
- **使用方式**：通过 Obsidian "模板" 核心插件或 Templater 插件插入。

### `8-素材库` — 素材库
- **用途**：存放笔记中引用的**图片、附件、文件**等非 Markdown 资源。
- **特点**：配合 Obsidian 的"附件存放路径"设置使用，保持笔记目录整洁。
- **内容**：截图、照片、PDF、音频文件、下载的参考资料等。
- **建议**：在 Obsidian 设置中将"附件默认存放路径"指向此文件夹。

### `9-插件` — 插件
- **用途**：存放 **Obsidian 插件相关**的配置说明、使用心得、自定义脚本。
- **内容**：
  - 插件的使用教程和个人配置
  - 自定义 CSS 片段
  - Dataview 查询脚本
  - 插件冲突或兼容性记录
- **示例**：`Dataview 常用查询.md`、`插件列表与用途.md`、`CSS 自定义样式.md`。

## 二、分类决策树

当新建一条笔记时，按以下顺序判断归属：

```
开始
  │
  ├─ 是临时想法、随手捕获或待处理链接吗？
  │    是 → 0-收件箱
  │
  ├─ 与有截止日期的具体任务或产出相关吗？
  │    是 → 1-项目
  │
  ├─ 是需要长期积累的学科或职责知识吗？
  │    是 → 2-领域
  │
  ├─ 是整理好的参考资料、学习笔记或读书笔记吗？
  │    是 → 3-资源库（再按下方"资源库内部决策树"细分）
  │
  ├─ 是已完成项目或过期信息的归档吗？
  │    是 → 4-存档
  │
  ├─ 是单一概念的知识卡片吗？
  │    是 → 5-卡片盒
  │
  ├─ 是每日记录或工作日志吗？
  │    是 → 6-日记
  │
  ├─ 是笔记模板框架吗？
  │    是 → 7-模板
  │
  ├─ 是图片、附件等非 Markdown 资源文件吗？
  │    是 → 8-素材库
  │
  └─ 是插件相关配置或脚本吗？
       是 → 9-插件
```

### 资源库内部决策树（3-资源库）

当一条笔记已判定属于 `3-资源库` 后，按**内容类型**继续细分到子文件夹：

```
进入 3-资源库
  │
  ├─ 是书籍/文章的读后感、书评或摘录吗？
  │    是 → 01-读书笔记
  │
  ├─ 是软件的安装、配置或使用教程吗？
  │    是 → 02-工具教程
  │
  ├─ 是对企业/项目/人物的商业模式或案例拆解吗？
  │    是 → 03-案例分析
  │
  ├─ 是语法、术语、概念等结构化知识参考吗？
  │    是 → 04-知识参考
  │
  ├─ 是个人电脑的软件清单、目录树或环境记录吗？
  │    是 → 05-环境清单
  │
  └─ 都不符合 → 留在 3-资源库 根目录，标注 #状态/待整理
```

### Agent 自动分类规则（资源库）

AI 在自动整理 `3-资源库` 时，按以下流程操作：

1. 读取笔记全文，判断其内容类型。
2. 按上方"资源库内部决策树"归类，将文件移动到对应子文件夹。
3. 若一篇笔记横跨多个类型（如"课程笔记"既有教程又有参考），**以主要用途为准**归入最主要的一类，次要类型用标签或 `[[双向链接]]` 补充。
4. 分类后，为笔记补充/修正 `#主题/` 与 `#类型/` 标签（默认类型标签见第一节）。
5. 移动文件后，将笔记内的相对链接（`[文字](文件.md)`）改写为 wikilink（`[[文件名]]`），避免跨文件夹断链。
6. 无法判断归属的，保留在 `3-资源库` 根目录并标注 `#状态/待整理`，待用户决定。

### 快速判断口诀

> 临时想法收件箱，任务项目有期限。
> 长期积累属领域，资料归档资源库。
> 资源入库再细分：书评归读书笔记，教程归工具教程，
> 案例拆解归案例，语法参考归知识参考，清单归环境清单。
> 做完封存入存档，一卡一概念卡片盒。
> 每日记录归日记，模板框架归模板。
> 图片附件素材库，插件配置归插件。

## 三、标签规范

### 1. 标签体系总览

所有标签使用 `#/` 层级结构，分为三类：**主题、类型、状态**。

### 2. 主题标签 — `#主题/`

标注笔记涉及的**知识领域或话题**。

| 标签 | 适用场景 |
|------|----------|
| `#主题/C++` | C++ 相关笔记 |
| `#主题/Linux` | Linux 系统相关 |
| `#主题/人工智能` | AI/ML 相关 |
| `#主题/个人成长` | 自我管理、效率方法论 |
| `#主题/投资理财` | 理财、投资相关 |
| `#主题/心理学` | 心理学知识 |
| `#主题/健身` | 健身、运动相关 |
| ... | 按需扩展，保持一致性 |

**规则**：主题标签从 `2-领域` 和 `3-资源库` 的目录名衍生，按需创建新主题。

### 3. 类型标签 — `#类型/`

标注笔记的**形式或体裁**。

| 标签 | 适用场景 |
|------|----------|
| `#类型/笔记` | 普通笔记（默认） |
| `#类型/文章` | 完整文章或长文 |
| `#类型/卡片` | 原子化卡片笔记 |
| `#类型/日记` | 每日记录 |
| `#类型/读书笔记` | 书籍摘要和读后感 |
| `#类型/模板` | 模板文件 |
| `#类型/清单` | 清单列表（TODO、检查表等） |
| `#类型/会议记录` | 会议纪要 |
| `#类型/项目` | 项目相关笔记 |

### 4. 评价系统 — `#评价/`

对于用户原创内容，AI 需在笔记末尾撰写一段**评价文字**，并附上 `#评价/` 标签作为简要标记。

#### 评价文字格式

评价文字应包含以下要素：
1. **总体评价**：用简单的话概括笔记的质量和亮点。
2. **具体分析**：指出内容中的优点、深度或独到之处。
3. **改进建议**：如有不足，给出可操作的建议。
4. **鼓励收尾**：以积极语气结束，鼓励持续学习。
5. **处理请求**：文中如有“这只是我个人的看法”“目前是这样想的”这类的话语，代表目前在这一方面的知识有所空缺，AI可以自由发挥。

#### 评价等级标签

| 标签 | 含义 |
|------|------|
| `#评价/优秀` | 理解透彻，表达清晰，有独立见解 |
| `#评价/良好` | 基本掌握，内容完整，有少量可改进之处 |
| `#评价/一般` | 理解尚浅，内容较浅显，需要进一步深入 |
| `#评价/待改进` | 内容有误、理解模糊或完成度不足，需重新整理 |

**规则**：
- 仅对**自己原创**的笔记撰写评价，转载/摘录内容无需评价。
- 评价文字由 AI 生成，用户可自行修改或补充。
- 每篇笔记**有且仅有一个**评价标签。
- 评价应客观、具体、有建设性，避免空泛套话。

### 5. 状态标签 — `#状态/`

标注笔记的**处理进度**。

| 标签 | 含义 |
|------|------|
| `#状态/待整理` | 刚放入收件箱，尚未归类 |
| `#状态/进行中` | 正在处理的笔记 |
| `#状态/已完成` | 内容已定稿 |
| `#状态/待复习` | 需要定期回顾的卡片 |
| `#状态/归档` | 已移入存档，不再修改 |

### 6. 标签使用示例

```markdown
# RAII 机制详解

- **定义**：Resource Acquisition Is Initialization，资源获取即初始化。
- **详解**：当对象被创建时，通过构造函数获取资源（如内存、文件句柄）；当对象生命周期结束时，通过析构函数自动释放资源。这确保了异常安全，无需手动管理。

---

> **AI 评价**：对 RAII 的核心概念理解准确，能用简洁的语言概括其工作原理，并提到了异常安全这一关键优势。建议后续可以补充一个具体的代码示例（如 `std::unique_ptr`），加深对资源所有权转移的理解。总体来看是一张质量不错的卡片。
>
> #主题/C++ #类型/卡片 #状态/已完成 #评价/良好
```

```markdown
# 2026-08-01 日记

今天学习了虚函数表的原理，理解了虚指针和虚表的工作机制，以及多态的实现基础。还做了一个小实验，验证了虚函数的动态绑定行为。

---

> **AI 评价**：今天的日记聚焦在 C++ 虚函数表这一核心概念上，内容扎实，能看出是经过动手实践后的总结。虚指针和虚表是理解多态的基石，你抓住了重点。如果能把实验中的代码片段和输出结果附上，会让这篇日记更有参考价值。继续保持动手验证的学习习惯！
>
> #类型/日记 #状态/已完成 #jack六年之约 #评价/良好
```

### 6. 标签使用原则

- **每篇笔记至少打一个类型标签**，以便快速筛选。
- **主题标签按需添加**，一篇笔记可以有多个主题标签。
- **状态标签有且仅有一个**，避免冲突。
- **评价标签有且仅有一个**（仅限原创内容），转载/摘录内容无需评价标签。
- **标签大小写**：统一使用中文/英文首字母大写，保持一致性。

## 四、文件夹与标签对照速查表

| 文件夹 | 默认类型标签 | 默认状态标签 | 典型主题标签 | 是否需要评价 |
|--------|-------------|-------------|-------------|-------------|
| 0-收件箱 | `#类型/笔记` | `#状态/待整理` | 按内容临时标注 | 否（临时内容） |
| 1-项目 | `#类型/项目` | `#状态/进行中` | 项目相关主题 | 是（项目总结时） |
| 2-领域 | `#类型/笔记` | `#状态/进行中` | 领域名称 | 是 |
| 3-资源库 | 按子类默认（见第一节）：`#类型/读书笔记` / `#类型/笔记` / `#类型/文章` / `#类型/清单` | 转载=`已完成`；原创按第五节判定 | 资源主题 | 是（原创笔记）/ 否（摘录） |
| 4-存档 | `#类型/笔记` | `#状态/归档` | 原主题保留 | 保留原评价 |
| 5-卡片盒 | `#类型/卡片` | `#状态/待复习` | 概念所属主题 | 是 |
| 6-日记 | `#类型/日记` | `#状态/已完成` | `#jack六年之约` | 是 |

## 五、状态判定标准（进行中 / 已完成）

> **统一原则**：`#状态/已完成` 不等于“内容写完了”，而是“这篇笔记/这件事达到了它的用途”。判定时不再依赖感觉，而是按以下各类型的具体标准核对；不满足即为 `进行中`。

### 判定标准

**`1-项目`**
- `进行中`：尚未交付当初启动时定义的产出目标。
- `已完成`：① 达成产出目标；② 有可交付物（能运行的代码 / 能用的文档 / 可复用的 skill）；③ 你确认不再继续迭代（或准备移入 `4-存档`）。
- 反例：写了函数但没跑通 = 进行中；调通 API 并收到回复 = 该阶段算完成。

**`2-领域`**
- 领域是“长期精进”，**原则上不设 `已完成`**，默认始终 `进行中`（或 `待复习`）。
- 仅当某领域明确“不再深耕、转只归档”时，才标归档进 `4-存档`。

**`3-资源库`（原创 vs 转载，标准不同）**
- **转载/摘录**（非本人撰写）：内容完整即 `已完成`（它是资料，只存在“要不要复习”的问题）。
- **原创笔记/读书笔记**：必须同时满足以下 **3 条**才算 `已完成`：
  1. 用你自己的话复述过核心（不是只贴原文）；
  2. 已附 `#评价/` 标签；
  3. 能通过“不看笔记能否讲得出来”的检验。
- **特别规定**：读书笔记若只是 AI 生成的摘要、你本人尚未阅读消化（缺上述 3 条），**一律 `进行中`**，绝不因内容完整而标完成。

**`5-卡片盒`**
- `已完成`：卡片独立、清晰、一个概念讲完、有来源、已归入对应来源子文件夹、已用 Wikilink 关联同来源卡片。
- `待复习`：默认状态，卡片写完后先挂 `待复习`，靠间隔复习消化。若尚未完成归类和关联，则先挂 `进行中`。

**`6-日记`**
- 天然 `已完成`（当日写毕），不需纠结。

### 兜底原则（改标签的依据）
> 当某篇笔记处于 `已完成`，但**缺少该类型的“已完成核心证据”**（如原创笔记无评价、读书笔记无复述、项目无可交付物），Agent 应自动将状态降为 `进行中` 并附评价说明原因——这就是“会改标签”的规则依据。

## 六、工作流建议

### 每日流程
1. 打开 `0-收件箱`，查看待处理笔记。
2. 按决策树归类，打上对应标签。
3. 处理 `6-日记`，记录当日内容。

### 每周回顾
1. 清理 `0-收件箱`，确保没有滞留内容。
2. 检查 `#状态/待整理` 的笔记，完成归类。
3. 回顾 `5-卡片盒` 中 `#状态/待复习` 的卡片。
4. 将已完成的项目移入 `4-存档`。
5. **核查标签是否过时（会改标签）**：扫描 `3-资源库` 等各目录，按第五节判定标准核查现有 `#状态/` 标签——若某笔记标 `已完成` 却缺“已完成核心证据”（如原创无评价、读书笔记未复述、项目无交付物），自动降为 `进行中` 并补评价说明；若内容已真正消化而仍标 `进行中`，则升为 `已完成`。

### AI 协助规则
- 当卡片盒关联一栏缺少或空缺时自动关联来自同一片文章的卡片
- **卡片自动归类与关联**：
  1. 当用户创建新卡片时，AI 应识别其来源，若来源已存在对应子文件夹则归入该文件夹；若不存在则自动创建新子文件夹。
  2. 当发现同一张来源下有新卡片时，AI 应自动在所有同来源卡片的"关联"字段中补全 Wikilink `[[卡片名]]`。
  3. AI 应定期扫描卡片盒，检查是否有遗漏关联的同来源卡片。
- 当新笔记放入 `0-收件箱` 时，AI 应主动询问是否需要归类。
- 根据笔记内容，AI 应推荐合适的文件夹和标签。
- 对于用户原创内容，AI 需在笔记末尾撰写一段**评价文字**（包含总体评价、具体分析、改进建议、鼓励收尾），并附上 `#评价/` 标签。
- AI 定期提醒用户清理收件箱和复习卡片。
- AI 应定期扫描 `3-资源库`，按"资源库内部决策树"自动归类新出现的笔记并移动文件（详见第二节"Agent 自动分类规则"）。
