# Person-op 检查清单与判据

## 一、四要素框架（写任何提示词都先过一遍）

|要素|问题|缺失的后果|
|---|---|---|
|角色|AI 以什么身份回答？|回答缺乏立场与专业深度|
|指令|具体做什么？|泛泛而谈|
|背景|受众/用途/前提是什么？|脑补业务背景|
|限制|格式/长度/边界是什么？|输出不可控|

## 二、五段式结构对照

1. 角色与目标（`<role>` / `<persona>`）
2. 背景知识与数据（`<context>` + XML 包裹，与指令隔离）
3. 行为规则（`<must_do>` / `<must_not>` / `<edge_cases>`）
4. 输出格式
5. 示例

## 三、清晰性五判据

- 明确受众与语气
- 规定输出篇幅
- 同时给出「要与不要」
- 说明最终用途
- 把复杂任务拆成步骤

> 清晰 ≠ 啰嗦：每个词都要有意义、无歧义。

## 四、输出格式控制三档（可靠性递增）

|档位|做法|适用|
|---|---|---|
|① 直接描述|JSON 字段 +「只输出 JSON，不要额外解释」|简单结构|
|② 模板填空|给带占位符的模板让 AI 填空|中结构|
|③ 预填充 Assistant|预填 Assistant 内容强制从指定位置继续|严格定位|

## 五、防幻觉五策略

1. 明确允许 AI 说「我不知道」
2. 限制只使用提供的信息
3. 先找证据再给结论（引用时指出处）
4. 要求标注置信度
5. API 场景 temperature 设为 0

## 六、Token 经济性速查

- 1000 token ≈ 750 英文单词 ≈ 500 汉字（中文更耗）
- 输出比输入贵 2-3 倍
- 长文档先摘要或只传相关片段（RAG）
- 多轮对话定期重置/压缩历史
- 超长任务拆提示词链，而非单条塞满

## 七、迭代检验固定问题（每轮对照）

1. 它做了要求它做的事吗？
2. 输出格式对吗？
3. 换一组输入还稳定吗？
4. 边界情况覆盖了吗？
5. 有没有多余/冗余的内容？

## 八、System 提示词要点

- 角色三要素：专业领域 + 行为方式 + 核心立场
- 核心规则控制在 500 token 内
- 关键指令放开头或结尾（避免 Lost in the Middle）
- 正面表述优于负面表述
- 用 few-shot 示例代替长篇描述
- 定期去除从未触发的冗余规则
