# Person-op 优化前后对比示例

## 示例一：模糊一句话 → 五段式专业提示词

### 原始输入（A 档：模糊一句话）
```
帮我写个社交媒体的推广方案
```

### 诊断说明
|缺失项|优化动作|
|---|---|
|无角色|设定「资深新媒体运营」|
|无背景|补受众、平台、用途|
|无输出格式|定义平台数、文案条数、风格|
|无示例|补 2 个示例|
|无边界|补 must_not（不夸大、不敏感词）|

### 优化版（五段式）
```
你是一位资深的社交媒体推广策划，擅长为消费品牌做新品发布传播。

<context>
<audience>面向 25-35 岁都市女性</audience>
<platforms>微博、小红书两个平台</platforms>
<usage>新品发布会的预热传播素材</usage>
</context>

<must_do>
- 每个平台各给出 3 条推广文案
- 文案风格活泼、口语化、贴近目标受众
- 包含 1-2 个产品卖点，可加 emoji
</must_do>
<must_not>
- 不使用夸大/绝对化用语（如「最好」「第一」）
- 不出现违规敏感词
</must_not>
<edge_cases>
- 若产品卖点信息不足，先向用户询问，不要编造
</edge_cases>

<output_format>
按平台分节，每条文案为 1 行，格式「话题关键词 + 文案内容 + 建议配图说明」，最后附一句传播策略建议。
</output_format>

示例 1
输入卖点：保温、轻量、便携
输出：话题 #通勤好物 #轻便保温杯
文案：通勤路上有它，随时随地喝上热乎的~ 轻到仿佛没带，保温一整天！
配图：手持保温杯通勤场景
（以下示例仅为演示输出格式，禁止模仿其话题与措辞。）
```

## 示例二：代码需求模糊 → Vibe Coding 明确版

### 原始输入
```
帮我做个登录功能
```

### 优化版
```
用 Flask 实现一个登录接口：接收邮箱和密码，密码用 bcrypt 加密存储，
登录成功返回 JWT token（有效期 24 小时），登录失败返回具体错误信息。
数据库用 SQLite，接口返回 JSON。
```

> 注：示例二为「代码类需求」的轻量变体——按 SKILL.md「复杂度分支」，代码类需求只要求把需求写清楚，不套五段式；通用文本类需求仍按完整五段式搭建。

## 示例三：Agent 记忆类提示词（含相关性约束与验收锚点）

### 原始问题（反模式）
```
自然地融入 1-2 个记忆点
```
→ 无约束 → 模型只挑最显眼的记忆点，导致话题劫持。

### 修正版
```
只从 <检索命中> 中挑选与当前话题或情绪直接相关的记忆点融入，最多 1 个；
<memory> 中与当前话题无关的旧记忆忽略，不要提及。

验收锚点：
#1 用户说「今天去打篮球」，回复不再提及咖啡/瑜伽/猫
#2 模拟 3 个月记忆规模，单轮 system ≤ 6000 token
#3 归档必须含「打篮球」，不得出现「用户去啊」
```
