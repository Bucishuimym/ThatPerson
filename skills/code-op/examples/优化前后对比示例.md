# Code-op 优化前后对比示例

## 示例一：C++ 计算器项目（真实反模式修复）

### 优化前（节选，含典型反模式）
```cpp
#include"computer.h"                    // 缺空格，include 在 guard 外
#include <iostream>
using namespace std;                    // .cpp 命名空间污染
#ifndef COMPUTREAM_H                    // 宏名拼错且与 #pragma once 重复
#define COMPUTREAM_H
...
class Real_number {                     // 类名 snake_case
public:
    Real_number(int r, int n, int o) : result(r), num(n), oper(o) {}
    void input();
    int pares_real_expression(string line);   // 拼写错误 + snake_case
    ...
private:
    int result;                         // int 存实数
};
```

### 诊断分级
|级别|问题|
|---|---|
|P0|复数 int 除法截断（1/2=0）；负数 char 传 isdigit 是 UB；throw 后不可达 return|
|P1|include guard 拼错且双写；#include 在 guard 外；using namespace std；display() 里 cin/cout 与计算耦合|
|P2|`Real_number`/`pares_real_expression` 命名问题；魔法数字 `cin.ignore(10000,'\n')`；system("pause")/system("chcp 936")|

### 优化后（节选）
```cpp
#pragma once                            // 防重包含只选一种
#include <limits>
#include "computer.h"                   // 本地头文件作首个包含，保证自包含

class RealNumber {                      // PascalCase
public:
    RealNumber(int r, int n, char o)    // 类型语义明确
        : result_(r), num_(n), oper_(o) {}
    int parseRealExpression(const std::string& line);  // 统一命名
    ...
private:
    int result_;
};
```

关键修复：
- 头文件 `#pragma once` 单独使用，宏名与文件名一致，include 进 guard。
- 移除 `using namespace std`，统一 `std::` 前缀。
- `cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n')` 替代魔法数字。
- 移除 `system("pause")` / `system("chcp 936")`，源文件编码统一 UTF-8。
- 复数实虚部改 double，除零检查后明确处理，删除不可达 return。

## 示例二：TypeScript 防御性降级与注入防护

### 优化前
```ts
function loadMemories(rootDir: string) {
  const text = fs.readFileSync(path.join(rootDir, userInput + '.md'), 'utf8');
  return text;   // 用户输入直接拼路径：路径穿越 + 无降级
}
```

### 优化后
```ts
const SECTION_FILES = new Set(['preferences', 'experiences', 'important_dates', 'identity', 'patterns']);
const DATE_RE = /^\d{4}-\d{2}-\d{2}$/;

function readIfExists(p: string): string | null {
  try { return fs.readFileSync(p, 'utf8'); }
  catch (e: any) { if (e.code === 'ENOENT') return null; throw e; }  // 防御性降级
}

function loadMemories(rootDir: string, userInput: string): string {
  const safe = path.basename(userInput);                    // 拒绝路径分隔符
  if (!SECTION_FILES.has(safe) || !DATE_RE.test(safe))      // 双白名单
    return '';                                              // 静默降级
  return readIfExists(path.resolve(rootDir, `${safe}.md`)) ?? '';
}
```

## 示例三：Bug 分析用「探针实证」而非猜测

差：「我觉得解析器可能把『去』当成动作了」
好：对编译产物 `dist/src/parser/archive.js` 直接喂真实对话文本，输出原始实证：
```
[经历/高] 用户去啊，感受：好喜欢        ← 实证：动作词错抓
```
据此逐条定位根因（正则最早位置匹配 ACTION_HINTS），并附代码行号速查。
