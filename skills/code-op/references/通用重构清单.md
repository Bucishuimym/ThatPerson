# Code-op 通用重构清单（P0/P1/P2 分级）

## P0 正确性与安全（先修，最高优先）

- [ ] 类型截断 / 精度丢失（如复数 int 存实虚部，除法截断）
- [ ] 未定义行为（如负数 char 传 `isdigit`，应 `static_cast<unsigned char>`）
- [ ] 注入面：用户输入未转义就落盘 / 拼接进模板
- [ ] Key / 敏感信息明文或落日志
- [ ] 路径穿越：用户输入直接拼路径，无白名单 + 前缀校验
- [ ] 联合类型当运行时校验（TS），无运行时白名单
- [ ] 除零 / 非法输入处理不明确（throw 后不可达 return）

## P1 结构与可维护性

- [ ] 重复实现 / 复制的配置 / 双源映射（收敛到单一事实源，统一 utils/）
- [ ] 职责未分离（UI/IO 与业务逻辑耦合在同一类/函数）
- [ ] 死代码、注释掉的代码、不可达代码
- [ ] 魔法数字 / 魔法值（改用常量或 `numeric_limits<streamsize>::max()`）
- [ ] 平台相关调用（`system("pause")` / `system("chcp")`）
- [ ] 契约/接口文件被擅自修改（应只实现/调用）
- [ ] 失败路径无防御性降级（缺文件/缺目录/数据损坏）
- [ ] 演示/测试数据污染真实数据（应独立目录、跑完即弃）

## P2 风格一致性

- [ ] 命名：类名 PascalCase、变量/函数风格统一，无 camel/snake 混用、无拼写错误
- [ ] 缩进：Tab 与空格统一，不混用
- [ ] 注释：语言/风格统一，`/// <summary>` 或项目既有惯例
- [ ] include/导入组织：guard 内、本地头文件作首个包含、标准库/系统库/本地分组
- [ ] 错误处理模式统一（全异常 或 全错误码，二选一）
- [ ] `using namespace` 与显式前缀同项目统一
- [ ] 代码格式：单语句 if 大括号、空格规范、等宽对齐

## 收尾

- [ ] 既有测试全部通过
- [ ] 新增测试锚点覆盖本次改动与边界（空输入/否定/冲突）
- [ ] 安全红线 8 条逐条复核
- [ ] 变更说明：改了哪些文件 / 为何改 / 验收标准
